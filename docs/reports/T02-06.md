## What was built

### Content pages (PUB-FR-011–013, PUB-FR-015)
- **Contracts** (`packages/contracts/src/content.ts`):
  - page types: PROJECT, GUIDE, CASE_STUDY and ABOUT
  - statuses: DRAFT, PUBLISHED and ARCHIVED
  - per-type structured parts (`CONTENT_DATA_SCHEMA`)
  - editable fields, including SEO, links, hero, featured, demo and position
  - admin and public views
- **Database** (migration `0019_content_search`):
  - `content_pages` holds a working copy plus a `published` snapshot. The site shows only the snapshot, so drafts and later edits stay private until publishing.
  - `content_page_media`
  - `search_documents` (generated `tsvector` plus trigram terms, GIN indexes), `search_phrases` and `search_events`
  - `help_requests` gains topic, company and phone
  - the `pg_trgm` and `fuzzystrmatch` extensions
- **Rich text** (`apps/api/src/catalogue/rich-text.ts`):
  - An allow-list cleaner keeps only headings, paragraphs, bold, italic, lists, links, quotes, images and guide diagram slots.
  - Images are allowed only from `/api/v1/media/<id>/…`. External links get `rel="noopener noreferrer"`.
  - The cleaner counts the scripts, inline handlers and other markup it removed. The editor shows the "Unsafe content removed" banner from that count (tested).
- **Admin API** (`/v1/admin/content`, CONTENT_MANAGE):
  - list, create, get and update (versioned)
  - publish, which refuses a guide without a summary and text
  - unpublish, archive and restore
  - Every change is audited. Publishing queues cache revalidation, a search refresh and IndexNow.
- **Public API**: `GET /v1/content?type=` (index) and `GET /v1/content/:type/:slug` (published only).
- **Admin screens** (Pen 106 · X3mMi, states pJPKT):
  - `/admin/content`: type tabs (Guides, Project pages, Case studies, About) and a table.
    - It covers the loading, empty ("No guides yet / Write the first guide."), error (request ID and "Try again") and 403 CONTENT_MANAGE states.
    - "New guide" (and the equivalents for other types) opens a dialog with Title, Address and "Create draft".
  - `/admin/content/:id`, the editor:
    - Record header: CONTENT PAGE · TYPE, title, status chip, author and saved time, plus Save draft, Preview and Publish.
    - Publish asks for confirmation ("Publish now"), then shows the "Guide published" banner.
    - Main column: page type, title, address, summary, the Tiptap rich text editor and a per-type **parts** form.
      - Rich text toolbar: bold, italic, heading, lists, link, image with required alt text, quote, and the guide's comparison and decision-aid slots.
      - The parts form is config-driven: repeatable, reorderable groups for kits, timelines, facts, comparisons and so on.
    - Side panels: SEO (title and description counters, canonical URL, "Allow search indexing" toggle), Linked items (products and pages), Hero image, Listing (featured, demo, position) and Status (unpublish, archive).
    - Unsaved changes warn before leaving the page.
  - `/admin/content/search-phrases`: add, list and remove everyday phrases. It also shows the search report: total searches, searches that found nothing, top searches and top no-result searches.
- **Public templates**, built from their Pen frames:
  - Projects directory (12) and project page (12B)
  - Our work (54) and case study (55)
  - Resources (56), guide (57) with its side contents list, and the phone jump menu (58)
  - About (59)
  - Contact (60): a structured enquiry that becomes a help request with the page it came from.

### Search (PUB-FR-006, 007, 016)
- One `search_documents` index across products, categories, project pages, guides and case studies. It is rebuilt by the `search.refresh` job on publish and at API and worker start.
- Weighted full-text search plus trigram similarity. Misspellings are corrected with Levenshtein ("polp" finds Polo, with "Search for that instead").
- Staff phrases lead straight to their target.
- Typeahead suggestions use the SEARCH limit.
- `/search`:
  - grouped results with type tabs
  - a no-result page that keeps the query and offers the closest things plus a custom request that carries the query to Contact
  - `noindex` on both the header and the meta tag
  - a click tracker (`search_events` stores redacted queries)
  - When the API rate limit trips, a "Search is busy" message replaces the error page.
- Header search on every page, and a full-screen search dialog on phones (Pen 08).

### SEO (PUB-SEO-001–009)
- Title and description rules plus canonical URLs (`lib/seo.ts`, `pageMetadata`).
- JSON-LD:
  - Organization and WebSite on the home page
  - Product with Offer only when the price is PRICE_READY (tested both ways)
  - BreadcrumbList, CollectionPage, Article (guides) and Service (project pages)
- Private route groups (`/admin`, `/account`, checkout and so on) send `x-robots-tag: noindex, nofollow` from the proxy.
- `robots.txt` and `sitemap.xml` list only published, indexable pages.
- IndexNow is pinged on publish (`seo.indexnow` job, with a key file route).

- "Unpublished changes" showed on every published page. Postgres `jsonb` reorders object keys, so comparing the snapshot with `JSON.stringify` always differed. The comparison now ignores key order, and a test covers it.

## Design comparison (Pen vs build, 1440 and 375)
The public templates were compared at 1440 against Pen 12, 12B, 54–60, 07, 08 and 10, with no horizontal overflow. Remaining differences:
1. **Photos**: project, case study and About photography doesn't exist yet. Cards and heroes fall back to the first named product's image. Real photos replace them through the editor's hero image.
2. **Project kit** (12B) is shown statically. Adding a kit to a quote belongs to T05-01.
3. **Editor header**: Pen shows Preview and Publish. A tertiary "Save draft" was added, because saving without publishing is a core action. Preview opens the live page, so it appears once a page has been published (there is no draft preview route; see Questions).
4. **Editor parts form, link pickers, Listing and Status panels** aren't drawn in Pen 106. They reuse the Pen 106 field, panel and toggle styles.
5. **Search phrases admin** has no Pen frame. It uses the admin list and panel pattern.
6. **Case study gallery**: the data model supports up to six images, but the editor has no gallery uploader yet. Use the hero image for now.

## Questions / deviations
- **Draft images are public by URL**: a content image becomes reachable at its media URL as soon as a non-archived page (a draft included) uses it. That lets the editor show it, but someone who guesses the file ID could see an unpublished image. Should this be tightened to published pages plus staff sessions?
- **No draft preview route.** Preview shows the live page only. A signed preview link would need a decision on who can see drafts.
- **Anonymous visitors attach files only after sending** a contact enquiry, because uploads need a session (TECH-04). Signed-in customers attach before sending.
- **Contact details** (email, phone, WhatsApp, address and map) are placeholders until they're verified (PUB-SEO-006).
- The editor inserts an image and then saves the draft immediately, because content images are served only once a page uses them.
