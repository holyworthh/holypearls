### Search (PUB-FR-006, 007, 016)
- One `search_documents` index across products, categories, project pages, guides and case studies. It is rebuilt by the `search.refresh` job on publish and at API and worker start.
- Weighted full-text search plus trigram similarity. Misspellings are corrected with Levenshtein ("polp" finds Polo, with "Search for that instead").
- Staff phrases (PUB-FR-007) do two things. In the typeahead each one is a shortcut that goes straight to its product, category or page. In full search the phrase is indexed with its target, so searching it ranks that target first.
- A phrase can point at a draft. It stays **inactive** (shown as INACTIVE in the admin, with the reason) and starts working when the target is published; unpublishing or archiving the target makes it inactive again.
- Typeahead suggestions use the SEARCH limit.
- `/search`:
  - grouped results with type tabs
  - a no-result page that keeps the query and offers the closest things plus a custom request that carries the query to Contact
  - `noindex` on both the header and the meta tag
  - a click tracker (`search_events` stores redacted queries)
  - When the API rate limit trips, a "Search is busy" message replaces the error page.
- Header search on every page, and a full-screen search dialog on phones (Pen 08).

### SEO (PUB-SEO-001–009)
- Title and description rules plus canonical URLs (`lib/seo.ts`, `pageMetadata`).
- JSON-LD:
  - Organization and WebSite on the home page
  - Product with Offer only when the price is PRICE_READY (tested both ways)
  - BreadcrumbList, CollectionPage, Article (guides) and Service (project pages)
- Private route groups (`/admin`, `/account`, checkout and so on) send `x-robots-tag: noindex, nofollow` from the proxy.
- `robots.txt` and `sitemap.xml` list only published, indexable pages.
- IndexNow is pinged on publish (`seo.indexnow` job, with a key file route).

## Review fixes (PR #30 principal engineer review)
1. **Draft images are private.** A content image is served by the public media route only while the live copy of a PUBLISHED page uses it. Publishing records exactly which images the live copy uses (`content_page_published_media`, migration `0020_content_publishing_media`, backfilled from existing snapshots); unpublishing and archiving remove them. Content images cache for five minutes instead of a year. Once a page is unpublished the API stops serving its images straight away, but a browser or shared cache that already fetched one may keep showing it for up to five minutes; unpublishing is not an instant revocation. If content ever becomes sensitive, use versioned or signed media URLs, a CDN purge or private storage. The editor shows draft images from a staff-only route, `GET /v1/admin/content/media/:fileId/:kind` (CONTENT_MANAGE, `private, no-store`).
2. **Publishing checks every image.** One validator covers the hero, images in the text and the case-study gallery. Saving needs each image to be a media-library upload; publishing needs it READY, an image type, with the rendition the page shows and alt text. It runs inside the publish transaction with the row locked, and errors come back per field (`heroFileId`, `body`, `data.gallery.1.fileId`).
3. **Status changes can't overwrite newer state.** Unpublish, archive and restore include the version in the write, so a stale request is refused with VERSION_CONFLICT and changes nothing. Restoring an archived page to draft now works (the editor's "Restore to draft" was refused before).
4. **Search events are kept for 90 days**, then removed by `cleanup.daily` (logged as `removedSearchEvents`). The report reads the last 30 days.
5. **Publication dates.** `published_at` keeps the first publication; the new `last_published_at` moves on each publish. Article JSON-LD uses them as `datePublished` and `dateModified`, and the sitemap uses the latest.
6. **Phrases for non-public targets** are kept but inactive (see Search above), and the admin shows their state.
7. **Phrase behaviour matches the docs**: typeahead shortcuts navigate; full search ranks.
8. **Spelling correction is bounded.** A `search_terms` lexicon with a trigram index is rebuilt with the index. Correction shortlists 20 candidates by trigram similarity, then compares edit distance; it looks up at most 4 words of 3–40 letters, and each lookup has a 500 ms statement timeout.
9. **No N+1 phrase lookups**: targets load in one query per type.
10. **Sitemap dates**: `/` and `/contact` carry no date; `/products`, `/projects`, `/resources` and `/our-work` are dated by the newest record they list.

## Re-review fixes (PR #30 re-review)
- **One destination per staff phrase.** A phrase is a shortcut, so it now leads to exactly one place. Phrases are compared after normalising (lower case, single spaces, trimmed). The API refuses a phrase already in use, naming its current destination ("This phrase already has a destination (Polo Shirt). Remove that phrase first to point it somewhere else."), and a unique index on `lower(phrase)` enforces the same rule if two requests race (migration `0021_search_phrase_one_destination`). The migration stops with a clear message if any phrase already has several destinations, rather than deleting one; checked against the dev database in a rolled-back transaction.
- The spelling-correction timing test only proves the lookup doesn't hang; the real guardrails are the limits in `CORRECTION` (words, candidates, statement timeout). Query-plan checks or latency metrics would be better regression protection later.

## Design comparison (Pen vs build, 1440 and 375)
The public templates were compared at 1440 against Pen 12, 12B, 54–60, 07, 08 and 10, with no horizontal overflow. Remaining differences:
1. **Photos**: project, case study and About photography doesn't exist yet. Cards and heroes fall back to the first named product's image. Real photos replace them through the editor's hero image.
2. **Project kit** (12B) is shown statically. Adding a kit to a quote belongs to T05-01.
3. **Editor header**: Pen shows Preview and Publish. A tertiary "Save draft" was added, because saving without publishing is a core action. Preview opens the live page, so it appears once a page has been published. There is no draft page preview (see Questions); draft images do show in the editor, from a staff-only route.
4. **Editor parts form, link pickers, Listing and Status panels** aren't drawn in Pen 106. They reuse the Pen 106 field, panel and toggle styles.
5. **Search phrases admin** has no Pen frame. It uses the admin list and panel pattern.
6. **Case study gallery**: the data model supports up to six images, but the editor has no gallery uploader yet. Use the hero image for now.

## Questions / deviations
- **No draft preview route.** Preview shows the live page only. A signed preview link would need a decision on who can see drafts.
- **Anonymous visitors attach files only after sending** a contact enquiry, because uploads need a session (TECH-04). Signed-in customers attach before sending.
- **Contact details** (email, phone, WhatsApp, address and map) are placeholders until they're verified (PUB-SEO-006).
