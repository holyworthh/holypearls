# T00-03 — API conventions

Status: DONE (merged after CI passed)

Commits / PR: branch `feature/t00-03-api-conventions`; pull request linked in `docs/tracker/TICKETS.csv`.

What was built:

- `packages/contracts`
  - `errors.ts`: the error-code registry (`VALIDATION_FAILED` 400, `NOT_SIGNED_IN` 401, `FORBIDDEN` 403, `NOT_FOUND` 404, `CONFLICT` 409, `RULE_FAILED` 422, `RATE_LIMITED` 429, `INTERNAL` 500), each with placeholder screen copy. It also holds `apiErrorSchema` (`code`, `message`, `fieldErrors?`, `context?`, `requestId`), `toFieldErrors()` and `REQUEST_ID_HEADER`.
  - `health.ts`: response schemas for the two health checks.
  - `money-wire.ts`: money crosses the API as `{ amountMinor: "<digits>", currency }`. `moneyWireSchema` parses it back to `Money`, and `toMoneyWire()` serialises it. This answers the T00-02 question.
  - `client.ts`: the typed API client `createApiClient()`. It parses every success response with its contract schema and throws a typed `ApiError` for non-2xx responses. It falls back to `INTERNAL` when the body is not the error shape.
- `apps/api`
  - `createApp()` sets up the Nest app. The `/v1` global prefix covers everything except `/health/live` and `/health/ready`, which sit at the root (TECH-07 §8).
  - `ZodValidationPipe` validates a request part with its contract schema. Failures return 400 `VALIDATION_FAILED` with `fieldErrors`.
  - `ErrorShapeFilter` sends every error, including Nest HTTP errors and malformed JSON, in the one error shape. Unknown errors become `INTERNAL` with no details and are logged with the request ID. A final fallback also returns 404 in the error shape for paths outside every route.
  - `AppError(code, { message, fieldErrors, context })` is the error that services and controllers throw.
  - Request IDs: the API keeps a well-formed incoming `x-request-id` header (8–64 characters of `[A-Za-z0-9_-]`) and otherwise creates `req_<uuidv7 hex>`. It returns the ID in the response header and in every error body.
  - JSON logs through pino. Every line carries `time`, `level`, `service` and `environment`, and each request writes one line with the request ID, method, route, status and duration. Nest's own logs go through the same logger.
  - Redaction walks each log object and replaces the value of any key that contains `authorization`, `cookie`, `password`, `secret`, `token`, `apikey`, `otp`, `emailcode`, `email`, `phone`, `cardnumber` or `cvv`. Matching ignores case, `-` and `_`. IDs and error codes are kept.
  - `/health/live` always returns `{ status: "ok" }`. `/health/ready` runs `select 1` with a 2-second timeout and returns 200, or 503 `unavailable`.
  - OpenAPI: `openapi.ts` builds an OpenAPI 3.1 document from the contract schemas using Zod 4's built-in `z.toJSONSchema`. The committed file is `apps/api/openapi.json`.
- Repository
  - `pnpm openapi:generate` writes `apps/api/openapi.json`. `pnpm check:openapi` regenerates it and fails when the committed file differs. The CI step now runs this real check, and the T00-01 placeholder script `scripts/check-foundation-artifacts.mjs` is removed.
- `apps/web`
  - `next.config.mjs` forwards `/api/*` to `${API_URL}/*` on the same domain.
  - `src/lib/api.ts` exports the browser client, which uses the `/api` base.

Questions / conflicts found:

- The validation demo route exists only in tests (`ConventionsController` in `app.test.ts`), per the approved plan. It is not part of the running API or the OpenAPI file.
- Logs redact `email` everywhere, per the approved plan. Later tickets should log customer and staff IDs instead.
- Endpoints are added to `openapi.ts` by hand from their contract schemas. When there are many endpoints, a later ticket could register routes and their schemas in one place so the controller and the document can't drift. The CI check already catches drift in the file itself.
- TECH-07 §10 says the web server creates the request ID too. The API accepts an incoming ID, but the Next.js server does not set one yet, because no server-side call exists. The first ticket with a server-side call should forward `x-request-id`.
- Error screen copy in `ERROR_CODES` is placeholder text until the PRD copy for each designed recovery screen is wired up.
