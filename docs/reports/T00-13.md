## What was built

| Finding | Fix and evidence |
| --- | --- |
| 1. Shared artwork deleted after copy/unlink | Copy/detach and cleanup coordinate on the file row. Surviving configuration links retain/repoint ownership. Cleanup checks relational references and frozen snapshots before deleting originals/renditions, rechecks after locking, and retains retry metadata when object deletion fails. Tests cover copies, retained snapshots, locks, retry and legacy rows filling a cleanup batch. |
| 2. Checked uploads overwritten by replay | S3/R2 PUT signatures require `If-None-Match: *`. The upload contract carries required headers through the browser caller. Local writes use an atomic, exclusive final link. Retrying a failed upload creates a new intent. Concurrent/replayed writes cannot replace checked bytes; real R2 returned 412 on replay. |
| 3. Revoked organization access survives personal ownership | Current membership/location access is checked before owner shortcuts for organization orders, quotes, projects, drafts and checkout; personal account lists filter that scope in SQL. | 4. Attached-file uploader bypass | Attached-record decisions are authoritative; unknown/malformed attached ownership denies access. Configuration, product, import batch, project, proof and problem owner policies cover legitimate callers. Tests cover revoked uploader, unknown owner, authorized owner, staff and record-specific guest access. |
| 5. Interrupted payment initialization loses recovery | Attempt, PROCESSING state and all seven existing verification jobs commit before calling Paystack. CREATED attempts are checkable. Ambiguous transport/provider outcomes remain recoverable; definite refusal reopens payment. Fault tests interrupt initialization, reject queue insertion and fail response persistence after provider acceptance. |
| 6. NGN and USD mixed in billing | Contract/API/UI expose separate currency totals. All sums remain integer minor units, with no conversion. Order and installment displays also pass the stored currency. API mixed-currency fixtures and two render regressions cover both totals and displayed symbols. |
| 7. Failed attempts and reviews suppressed | Payments owns a batched reader for schedules, receipts, latest attempts and OPEN reviews. Orders, quotes, workspace cards and receipt status use those facts. Paid direct orders with unresolved reviews show a contact warning; failed installments retain their actual status. |
| 8. Courier booking lost on database rollback | Migration 0059 (originally 0051; renumbered in the dev merge) adds a durable booking operation with one active operation per shipment. The external booking follows the prepare commit; ACCEPTED results survive local finalization failure. UNKNOWN blocks a fresh booking and manual status changes. Staff can record a verified BOOKED/NOT_BOOKED outcome with evidence; accepted local results and signed webhooks retry finalization without a second external booking. |
| 9. Limits hide older work and understate money | Scope/status/attention selection precedes limits. Full counts and yearly receipt totals span the authorized scope. Order history uses 50-row cursors; receipts use 100-row cursors with next/back links. Overview selects attention independently of recent active work. A fixture with 213 orders and 212 receipts exercises old unpaid work, tied timestamps, every page and location isolation. |
| 10. Per-order database reads | One page batches items, payment facts, proofs, placement names and holds. The populated order request measured 17 SELECTs, versus 1,809 in the original audit probe on this history (old 200-row cap, new 50-row page); the committed regression caps reads at 30. |
| 11. Incomplete workspace integration | Overview connects existing internal approvals, approved templates and active groups; search includes existing orders, projects, templates, groups and assets. Existing module readers enforce permissions and locations. Shared list components are reused by their original pages. Tests cover each result type, permission/location boundaries and empty results. |
| 12. Turbo strips integration keys | `SHIPBUBBLE_API_KEY` and `INDEXNOW_KEY` are included in Turbo's environment inputs. A strict-mode development run confirmed dummy values reached all four child processes. No real provider call was made by this check. |
| 13. Root development command omits admin | Root `pnpm dev` starts web, admin, API and worker. An isolated run returned HTTP 200 from both sites and API readiness and confirmed worker startup. |

Existing routes were extended rather than replaced: upload creation returns signed headers; organization orders/billing accept validated cursors; overview/search return the additional existing resource summaries; staff courier booking accepts an optional reconciliation decision. Migration `0059_courier_bookings.sql` (committed as 0051 before the dev merge) is additive. ## Permission rules

- An organization record's personal placer/uploader is subject to current organization membership and location scope.
- Attached files follow the attached record's server policy. Unknown owner policies fail closed.
- Workspace approval attention requires the existing approval permission, respects the separation rule and location scope, and does not expose other requesters' records to a Buyer.
- Groups require current location access before creator/manager shortcuts. Template, group and asset search reuse their module policies.
- Courier reconciliation requires the existing FULFILMENT_MANAGE and staff authentication/MFA checks. Provider request tokens and ambiguous results are private to staff; customers retain the normal shipment view.
- Invalid public page cursors return a validation error instead of silently reopening page one.

## Seed data and rollback

Permanent seed data is unchanged. Test helpers now use stored payment currency. Large histories, retained artwork, provider-fault triggers and reconciliation records are test fixtures only. Browser fixtures used test identities and disposable local records.

Deploy the API/contract consumers together, with migration 0059 first. Rolling back only the web app to a contract expecting one billing currency total is incompatible with the new response. For a rollback after courier operations exist, disable new booking and preserve the additive table/results for reconciliation; do not drop it or blindly rebook a shipment. Upload retries must keep the required signed header. R2 browser CORS must include that header.

Cleanup favors retention when a frozen snapshot still mentions a file ID. Billing intentionally reports every due balance; receipt and order history are paged. Very large numbers of simultaneously due orders still deserve a separate measured load exercise; the local fixture validates correctness and batching, not an unlimited scale claim.
