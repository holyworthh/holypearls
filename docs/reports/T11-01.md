### Data (migration 0042)

- **`brand_assets`:** `organization_id`, `name`, `kind` (LOGO, PRINT, EMBROIDERY, GUIDELINES, PACKAGING), `version`. Brand assets are organization-wide (TECH-03 §7: "explicitly organization-wide").
- **`brand_asset_versions`:**
  - Columns: `asset_id`, `number`, `file_id`, `status`, `review_note`, `reviewed_by_staff_id`, `reviewed_at`, `uploaded_by_user_id`.
  - Unique (`asset_id`, `number`), and one file per version.
  - Versions are never deleted or overwritten: uploading V5 adds a row and V4 is untouched (B2B-FR-023).
- **Files:** a new file purpose `BRAND_ASSET` (design files: PDF, AI, SVG, PNG or JPEG; 50 MB; private).

### Statuses (TECH-01 §4)

- **Normal path:** PROCESSING (file still being checked) → NEEDS_REVIEW (file ready) → PRODUCTION_READY (HolyPearls staff).
- **When the new version is approved:** the previous PRODUCTION_READY version becomes SUPERSEDED.
- **Retiring:** PRODUCTION_READY → RETIRED (the organization stops new use).
- **Archiving:** any status → ARCHIVED.
- **Each change** is one service function in one transaction, with an audit entry.
- **PROCESSING → NEEDS_REVIEW** happens when the version's file is READY. Checked whenever versions are read, because the file worker belongs to the files module.

### Permissions

- **Viewing:** any ACTIVE member sees the organization's assets.
- **Uploading, replacing, retiring and archiving:** `MANAGE_BRAND` (Owner and Admin).
- **Staff production review** (mark PRODUCTION_READY, keep in review with a note, retire, archive): `STAFF_ADMIN`. Frame 116 says the permission is "to be decided" and that "until then only STAFF_ADMIN sees it". Recorded under Questions.
- **Downloads:** members of the organization, `ORGANIZATION_SUPPORT` and `STAFF_ADMIN`.
- **Outsiders:** not a member is 404; a member without `MANAGE_BRAND` gets 403 on changes.

## Permission rules added

- **Viewing:** every ACTIVE member sees the organization's assets. Not a member is 404.
- **Changes:** create, replace, retire and archive need `MANAGE_BRAND`; others get 403.
- **Files:** only the person's own unattached `BRAND_ASSET` upload can become a version. Someone else's upload is 404, and an attached file is 400.
- **Staff review:** `STAFF_ADMIN` (frame 116's stated fallback). Non-staff get 404 and staff without it get 403.
- **Downloads:** members of the organization, `ORGANIZATION_SUPPORT` and `STAFF_ADMIN`.

## Differences from the design or PRD, and why

1. **Previews:** cards and the detail show the file's thumbnail once the worker has made one. Until then (and for PDF, AI and SVG originals, which are never shown) a placeholder with the asset's initials.
2. **Frame 66's "Approved use", "Minimum size" and "Colours" notes:** these aren't stored fields, so HolyPearls' review note carries the production guidance.
3. **"Used in N templates" and linked-template warnings** (frames 66, 67, 116) arrive with templates in T11-01b. The retire confirmation keeps frame 67's wording about orders already placed.
4. **Frame 116's automatic checks** (vector file, minimum size, colour count, outlined fonts) aren't run by the file worker. The reviewer checks by eye and writes the result in the note.
5. **Kind filters, and "Show archived"** in place of frame 65's "Status: Active" menu.

## Questions / conflicts found

1. **SUPERSEDED → RETIRED:** TECH-01 §4 lists only PRODUCTION_READY → RETIRED. PRD-05 B2B-FR-024 ("If V4 is still allowed…; if V4 is retired, templates move to NEEDS_REVIEW") and frames 67 and 116 retire V4 after V5 is ready, so a superseded version must be retirable. Following the higher source (the PRD). **Proposed TECH-01 §4 amendment:** "PRODUCTION_READY or SUPERSEDED → RETIRED".
2. **Which staff permission reviews assets:** frame 116 says "permission to be decided; until then only STAFF_ADMIN". Built with STAFF_ADMIN. PROOF_MANAGE ("Proofs & artwork") would fit the people who check artwork. **Owner to choose.** Proposed as a new ATTENTION item; the same question applies to template approval in T11-01b.
3. **"Kept in review":** the version stays NEEDS_REVIEW with HolyPearls' note. There's no "rejected" status in TECH-01; the organization uploads a new version.
