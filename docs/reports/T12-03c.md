## What was built

- **Branch:** `feature/t12-03c-csv-import`. **PR:** see the tracker row.
- **Migration `0050_csv_imports.sql`:**
  - **`import_batches`:** collection, the CSV file, file name, status (UPLOADED, CHECKED, IMPORTED, CANCELLED), headers, column mapping, who and when.
  - **`import_rows`:** each line's original cells, the matched values after fixes, problems, the participant it duplicates, the decision (MERGE, KEEP_BOTH, REPLACE, SKIP), the outcome (PENDING, IMPORTED, SKIPPED), and the participant it became. Lines are unique per batch.
  - **Participants** gain `import_batch_id` and `import_row`. `origin` is `IMPORT:<file name>`.
- **Contracts (`groups.ts`):** import fields and labels, duplicate decisions, the row, the batch (mapping, the collection's fields, counts, rows), and the start, match, fix and run inputs.
- **API (`groups/imports.ts`):**
  - **Upload:** the organizer's own CSV_IMPORT file, once the file check has finished (FILE_NOT_READY before). Up to 5,000 rows, plus a header row.
    - Every line becomes a row with its cells kept.
    - Columns are matched from their headers ("Work email" → email, "Chest name" → name on chest, "Delivery branch" → branch).
    - The file is attached to the batch.
  - **Check** (on upload, after any mapping change and after every fix), only for the fields the collection uses:
    - Name and email missing, or an email that isn't one.
    - A size that isn't an option (XS–4XL; "XXL" and "XXXL" read as 2XL and 3XL).
    - A name on chest over 12 letters, or with characters that can't be stitched.
    - Quantity from 1 to 50.
    - A branch that doesn't match an approved branch.
    - **Duplicates:** the same email as someone already in the collection (needs a choice), or as an earlier line in the file ("Same email as line 96").
  - **Fix a row:** change its values, or choose MERGE, KEEP_BOTH or REPLACE for a duplicate, or SKIP any row.
  - **Import:**
    - Rows with problems or an undecided duplicate stop it ("N rows need fixing first", with their lines), unless the organizer chooses to import the valid rows now (B2B-FR-071). Those rows stay PENDING to fix later.
    - SKIP rows become SKIPPED. Nothing else leaves a row out.
    - **New people** are created with their answers: SUBMITTED when everything the collection asks for is there, otherwise NOT_STARTED. While the collection takes answers, each gets their personal invite link by email.
    - **MERGE** fills in what the existing person hasn't answered; **REPLACE** uses the file's answers. Neither creates a second person.
    - Audited with counts.
  - **The CSV's contents are never logged:** the audit holds counts and ids only.
  - **OpenAPI:** the 6 routes are documented.
- **Customer site:**
  - **"Import from a spreadsheet"** on the organizer dashboard.
  - **The import page (frame 75):**
    - Steps (Upload, Match columns, Check rows, Import) and the upload with the format in words.
    - Three totals: rows in the file, ready to import, need fixing.
    - Each problem by line with its field and message, a field to correct it, Save and Skip.
    - Duplicates with "Choose what to do".
    - Column matching per field, and "Import N valid rows" with the fix-first note.
    - "Imported people get an invite link…".

## Permission rules added

- **Importing needs `MANAGE_COLLECTIONS`** for the collection's location. Viewers get 403.
- **Only your own uploaded CSV:** someone else's file is 404, and it must have passed the file check.
- **Seeing imports:** whoever can see the collection.

## Differences from the design or PRD, and why

1. **One fix field per row:** a row shows its first problem with a field to correct it. When it's fixed, the next problem (if any) shows. Frame 75 shows one problem per row too.
2. **Frame 75's "Leave for person to choose" for an empty size:** an empty size isn't a problem at all. The person is imported NOT_STARTED and picks their size with their invite link.
3. **Wholly blank lines** in the file are ignored by the CSV reader. They're not data, and line numbers count the remaining rows.
4. **Matching is per field** (each of the collection's fields picks a column) rather than per column.

## Questions / conflicts found

1. **Importing after the collection closes:** imports are allowed while CLOSED or in review. New people go into the review counts but don't get an invite link, because they can't answer until it reopens. **Owner to confirm** whether imports should be blocked after closing.
