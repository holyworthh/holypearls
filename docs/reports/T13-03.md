## What was built

- **Branch:** `feature/t13-03-operations-home`. **PR:** https://github.com/holyworthh/holypearls/pull/116.
- **API (`platform/ops-home.ts`, `GET /v1/admin/home`, any staff member):**
  - **The ten queues, each from its module's own list function** (so a queue counts exactly what its list shows):
    - **New Requests** (QUOTE_MANAGE): the requests queue, with "N waiting over 24 h".
    - **Quotes to Prepare** (QUOTE_MANAGE): quotes PENDING_REVIEW, with the oldest's age.
    - **Proofs and Artwork** (PROOF_MANAGE): proofs to prepare or check.
    - **Blocked Orders** (PRODUCTION_MANAGE): the board's Waiting and On hold groups ("N missing deposit or proof · N on hold").
    - **Production** (PRODUCTION_MANAGE): Queued and In production.
    - **Quality Check** (PRODUCTION_MANAGE): that group, with the oldest's age.
    - **Ready to Dispatch** (FULFILMENT_MANAGE): orders ready to ship, and items awaiting their balance.
    - **Payments Needing Attention** (PAYMENT_VIEW or PAYMENT_MANAGE): open payment reviews, and the DUPLICATE_PAYMENT count.
    - **Help Requests** (CUSTOMER_SUPPORT): OPEN.
    - **Problem Reports** (CUSTOMER_SUPPORT): NEW and triaged.
  - **Hidden queues:** each queue's permission is the one its list page (and sidebar section) needs. A queue the person can't see is never counted or sent (frame 95's note). The production board is loaded once, and only for production staff.
  - **OpenAPI:** documented.
- **Admin:**
  - **The home page** (`/`, frame 95): today's date, "Operations home", and a card per queue with its count, detail and "Open queue".
  - **Its states:** "All queues are clear" when every count is zero, "No work queues for your permissions", and the error state with the request ID.
  - **The production list** takes `?group=` (for example `WAITING,ON_HOLD`), so Blocked Orders, Production and Quality Check each open their own filtered list ("Showing Quality check · Show all groups").

## Permission rules added

- **`GET /v1/admin/home`:** any staff member, admin front end only. A customer gets 404.
- **Each queue** is shown only with the permission of the list it opens. Finance (PAYMENT_VIEW) sees only Payments Needing Attention; a STAFF_ADMIN-only person sees none.

## Differences from the design or PRD, and why

1. **Frame 95's "Queue visibility: permission to be decided" notice isn't shown.** Each queue uses its list's permission. **Owner decision (2026-10-19):** confirmed.
2. **No icons on the cards.** The admin has no icon set yet, so each card shows its label, count, detail and "Open queue".
3. **Details are what the lists know:** for example, Proofs and Artwork says "N to prepare or check" rather than frame 95's "2 files need cleanup".
4. **No loading state (frame 95 "Loading…").** The home is rendered on the server and arrives with its counts. A loading file for the whole admin shell would make "not found" pages answer 200 (seen on the account pages in T09-01b), so it isn't added.
