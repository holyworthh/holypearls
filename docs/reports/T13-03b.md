## What was built

- **Branch:** `feature/t13-03b-exports`. **PR:** see the tracker row.
- **Migration `0056_exports.sql`:** the `exports` table (platform). It holds:
  - the type and the date range (inclusive Lagos dates; none for the catalogue);
  - the state (GENERATING, READY, EXPIRED or FAILED), the file key, rows and failure;
  - who asked, and when it's ready and expires.
- **Job `export.generate`:** 15-minute timeout and two retries. After that, the dead-letter handler marks the export FAILED with "We couldn't build this file. Try again."
- **API (`platform/exports.ts`):**
  - **Each module builds its own rows,** so the platform never reads another module's tables (TECH-00 §5):
    - **Orders** (`orders`): number, placed, currency, goods, delivery, VAT, total, items, workspace order, cancelled, refund due.
    - **Payments** (`payments`): reference, what it was for, status, amounts, currency, channel, started, paid at.
    - **Customers** (`identity`): name, email, phone, email verified, account, first seen.
    - **Production** (`production`): each item of the orders placed in the range, with its status.
    - **Catalogue** (`catalogue`): every product as it is now, with no range.
    - **Collection totals** (`groups`): each order draft's pieces, names, counts by size and delivery points. No participant names.
  - **The worker writes a UTF-8 CSV** (with a byte-order mark, so Excel reads ₦) to `exports/<id>.csv` in private storage.
    - A cell starting with `=`, `+`, `-`, `@` or a tab gets a leading `'`, so spreadsheets don't run it as a formula.
    - A repeat delivery of the job does nothing.
  - **Routes (`/v1/admin/exports`, staff):**
    - List: the last 50 exports of the types the person may request, everyone's (frame 120 shows the team's list), plus those types.
    - Request, retry (failed only) and download.
    - **Download** returns a 5-minute link with a file name such as `holypearls-orders-2026-10-01-to-2026-10-19.csv`.
    - **Logging:** requests, retries and downloads are audited. Personal data is recorded with EXPORT_PERSONAL_DATA and the MFA time.
  - **Expiry:** after 24 hours an export shows as Expired and can't be downloaded. The daily clean-up deletes the file and marks the row EXPIRED.
  - **OpenAPI:** documented.
- **Admin `/exports` (frame 120):**
  - **"New export":** what to export (only the person's types), From and To dates (none for the catalogue), and the "Contains personal data" warning for Customers.
  - **Step-up dialog:** opens when the MFA check is older than 15 minutes ("Confirm and export").
  - **The list:** EXPORT, REQUESTED ("Ada · 2 min ago") and STATE: "Generating…", "Ready · expires in N h" with Download, "Expired", or "Failed · retry" with Retry.
  - **Checking back:** the page checks every 4 seconds while a file is generating, and shows "Export ready" when it's done.
  - **Other states:** "No exports yet", the error state with the request ID, and 403 for a person with no export permission.
  - **Sidebar:** "Exports" shows for anyone with an export permission.
- **Test people:** Ada (owner) now holds EXPORT_PERSONAL_DATA, as frame 120 shows her exporting customers.

## Permission rules added

| Export | Permission (any one) | Recent MFA |
|---|---|---|
| Orders, Payments | PAYMENT_VIEW, PAYMENT_MANAGE | no |
| Customers | EXPORT_PERSONAL_DATA | yes, on request and retry |
| Production | PRODUCTION_MANAGE | no |
| Catalogue | CATALOGUE_MANAGE, PRICING_MANAGE | no |
| Collection totals | PRODUCTION_MANAGE, QUOTE_MANAGE | no |

- A person sees and downloads only exports of their own types. With none of them, the list is 403. A customer gets 404.

## Differences from the design or PRD, and why

1. **The date range is two native date fields (From, To)** rather than frame 120's single range field.
2. **The orders and payments exports leave out names, emails and phone numbers.** Personal data sits only in the Customers export, which has the permission and MFA check. If orders should carry the customer's name, it becomes personal data and needs EXPORT_PERSONAL_DATA.
3. **Files are deleted by the daily clean-up (03:00 WAT),** so a file can stay in storage for up to a day after its 24 hours. It can't be downloaded once its 24 hours are up.
4. **The file is built in memory** (marked `ponytail:` in the code). If exports reach tens of thousands of rows, rows should be streamed to storage instead.
5. **No icons,** as on the operations home.
