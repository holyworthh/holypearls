# T00-02 — Database, migrations and test kit

Status: PARTIAL (implementation and local checks are complete; review and merge remain)

Commits / PR: branch `feature/t00-02-database-test-kit`; pull request linked in `docs/tracker/TICKETS.csv`.

What was built:

- `packages/db`: Drizzle ORM on node-postgres, an empty schema entry point, and a committed baseline migration (`drizzle/0000_baseline.sql`). The baseline contains no tables because business tables are out of scope. It proves that a database migrates from empty and records the migration.
- A separate migrate command: `pnpm db:migrate` builds `@holypearls/db` and runs `dist/migrate-cli.js`. No app process runs migrations on start (TECH-07 §6).
- `withTransaction(db, work)`: one transaction per change; any error rolls back every write and is rethrown.
- UUIDv7 IDs: `IdGenerator` interface, `uuidV7Generator` and `newId()` (TECH-00 §5 rule 6, TECH-01 §1).
- Column helpers for later tickets: `idColumn`, `createdAt`, `updatedAt` (`timestamptz`), `versionColumn` (optimistic locking), `amountMinorColumn` (`bigint`) and `currencyColumn` (`char(3)`).
- Money helpers in `packages/contracts` (browser-safe, so web and API share them): `Money` as `bigint` minor units plus `NGN` or `USD`; `money`, `fromMajor` (exact decimal string parsing), `toMajorString`, `add`, `subtract`, `multiply` (whole quantities), `sum`, `compare`, `equals`. Mixing currencies throws `CurrencyMismatchError`; nothing converts between currencies (TECH-05 §2).
- `packages/testkit`: `createTestDatabase()` creates a uniquely named, fully migrated database per test file and drops it afterwards, so tests never share data. `defineFactory()` is the factory skeleton. `runSeed()` loads seed steps in one transaction; `pnpm seed` migrates first and then runs it. Seed steps are empty until later tickets add fixtures, all labelled `TEST DATA`. The seed command refuses to run when `NODE_ENV=production`.
- Environment: `loadDatabaseEnv()` and `loadTestDatabaseEnv()` in `packages/config`. `TEST_DATABASE_URL` is optional and falls back to `DATABASE_URL`.
- CI: a PostgreSQL 17.6 service; migrate from empty, re-run on the migrated database, `db:check` (Drizzle consistency check plus a failure if the schema would generate an uncommitted migration), tests against the real database, and `pnpm seed`. The T00-01 "no migrations yet" placeholder check is removed; the OpenAPI placeholder stays for T00-03.

Questions / conflicts found:

- TECH-07 §6 asks CI to migrate "from the previous release" as well as from empty. There is no release yet. CI re-runs migrations on the already migrated database; a real previous-release check should be added with T00-08 (staging deployment), once a release exists.
- Money helpers live in `packages/contracts`, not `packages/db`, because TECH-00 §3 describes contracts as safe for the browser and the web app must display prices. The database column helpers stay in `packages/db`.
- `bigint` values are not JSON-serialisable. T00-03 should define how money crosses the API (for example `amountMinor` as a digit string in the Zod contract).

Seed data notes: The seed runner exists with no steps. Each ticket that adds tables adds its TECH-08 §11 fixtures to `seedSteps` in `packages/testkit/src/seed/index.ts`.
