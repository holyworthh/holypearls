# T01-05 — File uploads, previews and clean-up

Status: DONE (merged after CI passed). This ticket includes the former T01-06.

Commits / PR: branch `feature/t01-05-file-uploads-previews`; pull request linked in `docs/tracker/TICKETS.csv`.

## What was built

**Storage (`packages/storage`, TECH-04 §2)**

- `StorageAdapter`: presign upload, presign download, head, read the first bytes, read, write and remove.
- `S3Storage` for Cloudflare R2 in production or MinIO locally (AWS SDK v3 3.1141.0).
- `LocalDiskStorage` for development and tests, used because this machine has no Docker for MinIO. Its "presigned" URLs are HMAC-signed tokens for one object and one operation, with an expiry, served by the API's `/v1/local-storage/:token` route. A PUT can't exceed the size that was signed (413).
- `createStorage()` returns the private bucket and the **public-media bucket** (staff product images only).
- New variables: `STORAGE_DRIVER`, `LOCAL_STORAGE_DIR`, `S3_*`. `.storage/` is git-ignored.

**Files module (TECH-04 §3–8, §13)**

- Tables `files` (purpose, status PENDING_UPLOAD/PROCESSING/READY/NEEDS_REVIEW/REJECTED, owner, uploader, original and safe name, declared and detected type, real size, storage key, bucket, customer-readable reason, metadata) and `file_renditions`. Migration `0007_files`.
- Purposes and limits from TECH-04 §4: artwork 50 MB, attachments 25 MB, proofs 100 MB (PROOF_MANAGE), problem photos 15 MB, CSV 5 MB, product media 20 MB (CATALOGUE_MANAGE, public bucket). SVG, AI, EPS and PSD are not accepted.
- **Upload flow:**
  1. `POST /v1/files/uploads` (UPLOAD_INTENT limit) refuses a disallowed type or an oversized file **before signing**, checks who may attach, creates the row and returns a 15-minute URL for one object.
  2. The browser uploads directly.
  3. `POST /v1/files/:id/complete` checks the object exists and its real size, sets PROCESSING and queues `file.inspect`.
- **`file.inspect`** (2-minute timeout) reads the first 4 KB to find the real type (JPEG, PNG, WebP, PDF or CSV by content). A type that isn't allowed, or doesn't match the claim, is REJECTED with "This isn't a file we can use. Upload JPEG, PNG or PDF. For AI, EPS or SVG files, ask us for design help."
- **`file.preview`** (2 retries, 2-minute timeout):
  - Images: sharp makes a 2,000 px preview and a 400 px thumbnail (WebP), with EXIF and other metadata stripped.
  - PDFs: MuPDF (WebAssembly) renders pages in a **separate child process** with a 60-second kill timer, a 1 GB heap limit and an empty environment. It renders the first page, or every page up to 20 for proofs, plus a thumbnail.
  - A file that can't be previewed becomes **NEEDS_REVIEW** with a reason, not an error loop. A preview job that dead-letters also becomes NEEDS_REVIEW. CSVs go straight to READY.
- **Downloads:** `GET /v1/files/:id/download` returns a 5-minute URL for the original; `GET /v1/files/:id/preview?kind=preview|thumbnail|page` returns 5-minute preview URLs. They are never stored or logged.
- **Ownership (TECH-04 §7):**
  - `FILE_OWNERS` is a registry per record type; the first is HELP_REQUEST, which uses the help request policy.
  - Before a file is attached, only its uploader (user or guest session) can use it. Staff files are visible to staff holding the purpose's permission.
  - Everyone else gets 404. Knowing an ID or a storage key never grants access.
  - `attachFile(tx, fileId, owner)` lets modules attach inside their own transaction.
- **`cleanup.daily`** (scheduled at 03:00 Africa/Lagos in the worker):
  - removes uploads never attached to anything after 7 days, with their previews
  - removes finished rate-limit windows, expired idempotency keys, expired guest sessions, and used or expired email codes

**Upload component (COM-FR-052, Pen HP/Form/FileUpload)**

- `FileUpload`: drag and drop or "Browse files"; real upload progress (`XMLHttpRequest`, because fetch can't report upload progress) with a progress bar; "Checking file…" while the worker checks it.
- Ready with a thumbnail and "Uploaded · PNG · 2400 × 1600"; NEEDS_REVIEW and REJECTED show their reason and "Try another file"; a failed upload shows Retry, which re-sends the same file; Remove.
- Layout per Pen: bone, dashed strong line, 24 px padding, 10 px radius. It is on the `/dev/slice` demo page, and the uploaded file is added to the "Need help" context.

## Questions / conflicts found

- **Design against TECH, file types:** RESOLVED 2026-09-28. The owner chose to accept SVG and AI, as Pen shows. Built on `feature/t01-05-svg-ai-uploads`; TECH-04 §4 amended; see `docs/research/UPLOAD-FORMATS.md`.
- **No network for the PDF renderer:** Node 22 has no simple per-process network block. The renderer is WebAssembly MuPDF reading bytes from IPC, and has no network code. For full isolation, run the worker's PDF step in a container with no network egress on the host (T15-02 security hardening).
- **Local storage in development:** without Docker, files live under `.storage/`, and the API serves signed URLs itself. With MinIO (`docker compose up minio`) or R2, set `STORAGE_DRIVER=s3`; the browser then uploads to the bucket directly. **R2 needs a CORS rule** allowing PUT from the web origin; add it with the staging set-up (T00-04).
- **Low-resolution check:** "NEEDS_REVIEW for low resolution at the intended print size" (TECH-04 §3) needs the print size, which comes from the configuration (T03-07). The status and reason fields support it.
