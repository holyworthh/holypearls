# T15-01: Permission attack suite, security headers and abuse limits

Status: IN REVIEW. Branch `feature/t15-01-attack-suite-headers-limits`.

## Plan (approved in advance by the owner)

- One generated access test over every route the NestJS router serves (`apps/api/src/route-access.test.ts`, route list from `testing/routes.ts`). Anything not listed as open is private, so a new route fails closed.
- Script nonces per page request (TECH-06 §9) in both Next apps' `proxy.ts`; the CSP moved out of `next.config.mjs`. Every page renders per request (Q1: accepted; tagged fetch caching and `revalidateTag` still work, only full-route HTML caching ends).
- Open-redirect fix: `/\host` and `/<TAB>/host` were accepted by `safeNext` and the contracts. One `isRelativePath` now backs both, and the auth routes check `callbackURL`, `errorCallbackURL`, `newUserCallbackURL` and `redirectTo` themselves.
- Abuse-limit tests for guest links, email codes, uploads and contact; the web server's own cached reads skip the PUBLIC_READ address limit.
- Upload abuse tests (hostile file names, pixel bomb) and two ID-mixing tests (receipt, proof).
- Q2: the T14-05 dependency is TODO; the owner runs tickets in parallel, so this proceeds and is recorded here. Q3: `pnpm audit --prod --audit-level high` stays as is (ci.yml:57-58). No CI change: the new tests run inside `pnpm test` and `test:e2e`.

## Real access holes found by the generated test, and the root fixes

1. **Writes read their body before checking who is asking.** About 70 private write routes (organizations, collections, stores, templates, checkouts, projects, proofs, quotes, orders, me, uploads and more) returned `400 VALIDATION_FAILED` to a signed-out caller, because `ZodValidationPipe` runs before the handler resolves the actor. No record data leaked, but the response depended on the route's body schema, not on identity. The plan's fix (move `getActor` before `parse` in each controller) can't work with pipes, so the root fix is one global `IdentifiedGuard` (`identity/identified.guard.js`): a write needs a sign-in, a guest session or a device cookie, otherwise `401 NOT_SIGNED_IN` before any body is read. The 22 writes that really are open carry `@Public()` (cart, first draft/checkout/project, help request, order find, email codes, guest-link redeem, guest-session end, invitations, collection join/invite, price check, search clicks, both webhooks, demo slice). A new write is private until marked. Admin routes are skipped (StaffGuard gives outsiders 404).
2. **Writes with no rate-limit class:** `PATCH /v1/me/profile`, `POST /v1/me/sessions/revoke-all`, `DELETE /v1/me/sessions/:sessionId`, `POST /v1/files/:id/complete` now `COMMERCIAL_WRITE`.
3. **Admin writes with no `ADMIN_WRITE` class:** `POST /v1/admin/exports`, `/exports/:id/retry`, `/exports/:id/download`, `POST /v1/admin/monitoring/test-error`, `POST /v1/admin/recommendation-rules/:type/preview` now `ADMIN_WRITE`.
4. **Open redirect** (above).
5. API responses lacked `Permissions-Policy`; web `/api/*` responses carried two CSP headers. Both fixed.

No route was added to `OPEN_ROUTES` to make a failure go away, and no expected status was loosened in the generated test. Allow-list entries: `OPEN_ROUTES` (41, each with a reason), `RATE_LIMIT_EXEMPT` (two webhooks, DELETE guest-session), `STRANGER_EXEMPT` (`GET /v1/me/history/:list`: `:list` names a list, not a record).

### Existing tests changed because of fix 1

Six tests had a brand-new cookie-less browser writing to someone else's record and expected 404 (`tracking`, `payments`, `quotes`, `cart`, `shipments`, `projects`). That caller now gets 401 before the record is looked up, which TECH-03 §12 also allows. They use the new `expectNoIdentity` helper (401 or 404). `app.test.ts` and `demo-slice` routes are marked `@Public()`.

## Differences from the plan

- Fix for the signed-out 400s is the global guard, not per-controller reordering (pipes run before handlers).
- Fixture flows run on a second API instance on the same database with one front end (the separated harness 404s admin calls from the flow helpers).
- `ROUTE_REPORT=<file>` writes the table to a file instead of printing it.
- `app.ts`/`rate-limit.ts` changes for the guard, `FRONT_END_SERVER` and Permissions-Policy landed in commit 1 because it needs them; commits 4 and 5 hold the rest.
- Absolute URLs whose origin is the web or admin origin are also accepted by the auth-route redirect check (the library puts absolute links in emails).
- Fixture guest (not the paid-order browser) owns the file and help-request fixtures, since a browser with only a device cookie can't upload.
