## What was built

### Public read API (`/v1/catalogue/*`, PUBLIC_READ limit, `Cache-Control: public, max-age=60, stale-while-revalidate=300`)
- **Only visible records leave the API.** A product is shown only when all of these hold:
  - it is PUBLISHED or TEMPORARILY_UNAVAILABLE
  - it is listed
  - its category and that category's parent are PUBLISHED
- DRAFT and ARCHIVED products and unpublished categories never appear (tested). Staff-only fields (SKU, version) are never included.
- `GET /v1/catalogue/navigation`: the category tree with visible product counts, the admin-managed "popular" list for the mega-menu, the homepage's "Most ordered" cards and the total product count. One call feeds the header, mega-menu, footer and homepage.
- `GET /v1/catalogue/products`: the Product Directory. It offers:
  - search over name, summary and the staff-added everyday phrases (PUB-FR-007 phrases already count)
  - filters by category (a top-level category includes its subcategories), product family and buying mode
  - sort by most ordered (the order of the "Most ordered" list), name or newest
  - numbered pages
  - facet counts per filter, computed without that filter itself, so each chip shows what it would give
- `GET /v1/catalogue/products/:slug`: one product's public data (images, specifications, FAQ, related, SEO).
- `GET /v1/catalogue/hubs/:slug`: a category hub. It returns the published hub sections (or the default ones), featured products, subcategories and the category's products.
- `GET /v1/media/:fileId/preview|thumbnail`: public images. The image is served only when the file is a READY product-media file on a visible product or a published category, so draft products' images stay private (tested). It has stable URLs, is cached for a year (`immutable`) and sends `nosniff`.

### Admin
- **Category hub editor** (Pen 105, `/admin/categories/:id/hub`, linked from the category editor as "Edit hub page sections →"):
  - eight sections: summary, subcategories, featured, grid, guidance (comparison table), process (production routes), FAQ and related links
  - show or hide each section, and reorder with Move up / Move down (keyboard)
  - edit each section's fields; Save draft; Publish changes
  - the "Unpublished changes" chip and the published time
  - drafts never change the public page until published
  - optimistic versioning (409); audited; publishing refreshes the `category:<slug>` and `catalogue` cache tags
- **Menus & homepage** (`/admin/merchandising`, new nav item): the two admin-managed lists, "Mega-menu · popular products" and "Homepage · most ordered". Staff search to add, reorder, remove and save. Saves are versioned and audited, and refresh the `catalogue` tag. Unpublished products in a list are skipped on the site.
- API: `GET/PUT /v1/admin/catalogue/categories/:id/hub`, `POST …/hub/publish`, `GET /v1/admin/catalogue/lists`, `PUT /v1/admin/catalogue/lists/:key`. All require CATALOGUE_MANAGE (403 for other staff, 404 for customers).

- **Category hub** `/categories/:slug` (Pen 18 and 11, PUB-FR-009):
  - server-rendered from the published hub
  - breadcrumb, then sections in the chosen order
  - canonical URL and SEO title and description from the category

- **Product page (first version)** `/products/:slug`: breadcrumb, main image, summary, what happens next (configure, quote or project, from the buying mode), description, specifications, FAQ and "You may also need". T03-03 replaces it with the full template and configurator. It exists now so every card and menu link lands somewhere (the "reachable in 3 clicks" check).
- **Contact** `/contact?topic=…`: the "Can't find it? Tell us what you need" route (PUB-FR-004), plus quote, product, order, artwork and delivery topics. It uses the existing help-request form with the page's context.
- **Caching:** public server fetches send no cookies and are cached by Next under tags (`catalogue`, `category:<slug>`, `product:<slug>`, `directory`, `navigation`), with a 5-minute fallback. Every admin change that affects public pages queues `cache.revalidate`, which calls `/internal/revalidate` (T02-01). The homepage renders per request, so a build without the API can't freeze empty menus; its data still comes from the tagged cache.
- **Seed:** the two lists start with sample products (Polo Shirt, Business Cards, Roll-Up Banner…).

## Differences from the design

1. **Directory filters:** Pen's rail has How it's made, Price, Quantity, Decoration and Needed by. Those fields arrive with product rules and prices (T03-01, T03-08). The rail has **How it's bought** (the buying modes) and **Product type** (the family) until then.
2. **Card price line:** Pen shows "From ₦8,500 / piece · Min 10". Prices come from T03-01, so the line shows the price state ("See the price as you choose options", "Priced by quote after we review it"…).
3. **Directory feature row and editorial image:** Pen's large feature row and the photo in the "Made from scratch" interrupt need real photography. The interrupt is built as a dark text panel after the results. "Load more" isn't built; numbered pages are.
4. **Homepage concept stories:** Pen's "One event, one order" project story, "Reorder in minutes" company accounts and the production photo register describe features that don't exist yet (projects T05, workspaces T10) and use temporary reference imagery. They're left out so the homepage promises nothing that isn't built; add them when those features ship. "How it's made" is a text band. The hero uses the first "Most ordered" product photo rather than Pen's production photo.
5. **Header bag icon:** there's no cart until T04-01, so it's omitted. The track-order icon goes to the contact page (order topic) until order tracking exists (T07-03).
6. **Our Work and Resources** link to the homepage's "How it's made" and "How ordering works" sections until T02-06 builds those pages. The Projects mega-menu's goals lead to the matching category hubs until T05-01 builds the project builder.
7. **Footer:** the newsletter signup is left out; there's no newsletter feature or consent handling yet. The Privacy, Terms and Accessibility links are left out until those pages exist.
8. **Hub hero images** (Pen 18's three photos) need real photography. The hub hero is text with the category's actions.
9. **Hub editor:** "Preview draft" isn't built; "View live page" opens the public page. Reordering is Move up / Move down (Pen's keyboard alternative) rather than drag. The featured-products field takes page addresses, one per line.

## Questions / conflicts found

- **Links to pages from later tickets:** Projects, Our Work and Resources have no pages until T02-06 and T05-01. They point at the closest existing pages (see difference 6) rather than at pages that would 404.
- **Server-side rate limit:** public reads use PUBLIC_READ (300 per minute per IP). Pages rendered on Vercel reach the API from Vercel's addresses, so heavy traffic could share one limit. The tagged cache keeps API calls rare, but consider letting the web server identify itself (a shared secret header) so its calls use a separate, higher limit (T15-01).
- **"Most ordered" ordering:** there are no orders yet, so "most ordered" means the admin list's order, then name. Once orders exist (T04-05), sort by real order counts and keep the list for the homepage.
