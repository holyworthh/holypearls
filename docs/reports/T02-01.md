# T02-01 — Catalogue data model, seed and admin

Status: DONE (pending CI and merge). Part 1 (#14) built the data model, seed, admin API and the product list and editor. Part 2 (`feature/t02-01-catalogue-admin-part-2`) adds everything the report listed as left to do.

Commits / PR: part 1 in #14; part 2 on `feature/t02-01-catalogue-admin-part-2`. The pull requests are linked in `docs/tracker/TICKETS.csv`.

## What was built

- **Schema** (migration `0008_catalogue`):
  - `categories`: a tree with slug, name, description, position, status DRAFT/PUBLISHED/ARCHIVED, SEO fields, hero image and version.
  - `products`: SKU, slug, name, summary, description, family, buying mode, category, status, whether it's listed, search phrases, specifications, FAQs, SEO fields, publish time and version.
  - `product_options` and `product_option_values`: reusable option groups; variants stay on one product (PUB-SEO-002).
  - `product_media`: images from public-media files.
  - `product_relations`: related products; a product can't be related to itself.
- **Product families:** the 10 archetypes from the Stage 1.4 seed sheet: GARMENT, APPAREL_PRINT, EMBROIDERY, PAPER_PRINT, LARGE_FORMAT, PACKAGING, STICKER_LABEL, PROMOTIONAL_ITEM, WALL_ART and CUSTOM_PROJECT.
- **Buying modes** (PRD-02 §3): SIMPLE_CONFIGURABLE, CONFIGURABLE_QUOTE and CONSULTATIVE_PROJECT. These map from the sheet's DIRECT_CONFIGURE, CONFIGURE_QUOTE and PROJECT_QUOTE.
- **Seed (TEST DATA):**
  - The nine canonical categories (Stage 1.2), with subcategories.
  - One published product per family, from the sheet: Polo Shirt, Heat Transfer Printing, Flat Embroidery, Business Cards, Roll-Up Banner, Small Paper Bag, Label Sticker, Standard Mug, Landscape Canvas, and Team & Staff Branding.
  - Each has sample options (colour, paper, size…).
  - Re-running the seed changes nothing. Prices wait for T03-01.
- **Admin API** (CATALOGUE_MANAGE; 403 for other staff, 404 for customers):
  - list with search, status and family filters and cursor paging
  - create a DRAFT product
  - edit with optimistic locking: 409 `VERSION_CONFLICT` (a new error code) when someone saved first
  - change status: publish, mark temporarily unavailable, archive (no way back to DRAFT; see Questions)
  - Every change is audited with before and after.
  - Publishing needs at least one image, an SEO title and a short description (Pen frame 98 validation state); otherwise 422 with field errors.
  - Each public status change queues `cache.revalidate` for the tags `product:<slug>` and `catalogue`. The worker posts them to `WEB_REVALIDATE_URL` when that is set.
- **Screens:**
  - `/admin/products` (Pen 96): filters, table and empty, error and 403 states.
  - `/admin/products/:id` (Pen 98): details, buying mode, search phrases, short description and SEO title. The publishing panel has the status, publish confirmation, save draft, unsaved-changes hint, validation notice, temporarily-unavailable, unpublish and archive confirmations, and the audit note.

## Part 2 (built 2026-09-28)

- **Status rule:** products can no longer go back to DRAFT. To take one off the site, archive it (owner decision). "Unpublish" is gone from the editor and the bulk bar.
- **Bulk select and actions** (Pen 96): a checkbox per row and "select all on this page"; the dark bulk bar with Publish, Mark temporarily unavailable and Archive, each confirmed. API `POST /v1/admin/catalogue/products/bulk-status` checks and audits each product on its own. It lists the ones it skipped with a reason, for example "Already TEMPORARILY_UNAVAILABLE" or "Not ready to publish". The success notice uses Pen's wording.
- **Editor tabs** (Pen 98): Details, Media, Specifications & FAQ, SEO and Related.
  - Details: name, family and category (now editable), buying mode, search phrases, short and full description.
  - Media: upload product images (FileUpload, purpose PRODUCT_MEDIA), alt text, move up and down (the first image is the main one), remove. A published product keeps at least one image. Images under 1600 px wide are REJECTED with Pen 104's message.
  - Specifications & FAQ: add, edit and remove label/value pairs and questions.
  - SEO: SEO title and description with character counts, and the page address.
  - Related: search and add up to 12 products, reorder, remove. A product is never related to itself.
- **New product** page (`/admin/products/new`): name, SKU, page address (filled from the name), family, category and buying mode. It creates a DRAFT and opens the editor.
- **Categories** (Pen 104, `/admin/categories`, new "Categories" nav link): a table with parent, product count and status, and the editor panel (name, parent, page address, description, SEO title and description, hero image upload).
  - Save, Save and publish, and Archive with Pen's confirmation text.
  - Two levels only (top level and subcategory).
  - A subcategory can't be published before its parent.
  - A category with products or live subcategories can't be archived; staff are told to move or archive the products first.
  - Everything is audited and refreshes the `category:<slug>` and `catalogue` cache tags.
- **Page refresh:** the web route `POST /internal/revalidate` (Bearer `WEB_REVALIDATE_SECRET`) calls `revalidateTag` for each tag. The worker already posts to `WEB_REVALIDATE_URL`.
- **Sample images (TEST DATA):** one generated product photo per seeded product (2000 × 1500 WebP, `packages/testkit/assets/products`), made in Pen with its image generator. The seed writes them to the public-media store and links them with alt text. It skips products that already have images.
- **Fixes found on the way:**
  - Local file storage: the private and public-media folders signed URLs with the same key, so a public image URL was checked against the private folder and refused. An upload of a product image could also land in the wrong folder. Each folder now signs with its own key.
  - A relative `LOCAL_STORAGE_DIR` now resolves from the repository root, so the api, worker and seed share one `.storage` folder.
  - Category subqueries now name their table explicitly. Drizzle drops table names in single-table queries, and the product counts came out as 0.

## Questions / conflicts found

- **Unpublish:** RESOLVED 2026-09-28. The owner decided products are archived, never unpublished. That matches TECH-01 §4 as written (no way back to DRAFT), so no document change is needed. Pen frames 96, 98 and 104 still show "Unpublish"; the design file should drop it.
- **Staging page refresh:** the Vercel staging URL sits behind Vercel's login, so the worker's revalidation calls to staging would be refused. `WEB_REVALIDATE_URL` is set only for production.
- **Sample images on staging:** staging stores files on the container's disk until R2 keys exist, so seeded images disappear when the container restarts. Re-run the seed after a restart, or add R2 keys.
- **Seeded products are PUBLISHED without images.** That lets public pages (T02-03) have content. Staff publishing still requires an image.
